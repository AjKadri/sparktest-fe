# Sparktest proof

Generated by `scripts/proof.py` (run `./scripts/proof.sh`); do not edit by hand. Expected minimums were committed before the results commit
of each step, in [EXPECTATIONS.md](EXPECTATIONS.md). Case numbers are 1-based. "found" is the shrunk (minimal) counterexample.
Sparktest shrinks greedily, so it finds a local minimum, not always the global one.

## Summary

- Planted bugs: 5/5 found and shrunk; 5/5 minimums as pre-registered. Fixed versions passing: 5/5.
- Sonatina and native agree exactly (case, steps, original, shrunk) on 22/22 pure properties.
- std: 12/12 properties hold (no Fe bug found).
- ERC20 test fixture from the Fe compiler repo (see below): all 5 required properties plus a conservation property hold on the unchanged fixture; the planted self-transfer bug is caught and shrunk by 2 properties, with raw `u8` actors and again with `Index<4>` actors.
- A contract that really panics (`examples/rewards`): found through `try_call` and shrunk to the exact boundary stake; the same property through a direct `evm.call` reverts the whole test with no report.

Honest notes:
- `fee_buggy` shrinks to the global smallest overflow, amount=1,844,674,407,370,956 at bps=10000 (the table below), thanks to the joint moves added in L7c. Before them, per-component shrinking stopped at a local minimum (bps=127, amount ~1.45e17). The pre-registered criterion (a boundary case: amount*bps >= 2^64 and (amount-1)*bps < 2^64) is met.
- ERC20 buggy copy: the pre-registered minimum (0, 0, 1) was only partly reached: the structure (a self-transfer of amount 1) is exact, but the actor indices are raw u8 values taken `% 4`, and shrinking them to 0 would change the actor, so they stop at e.g. (21, 125). `Index<N>` (added in L4.1, amendment tables below) keeps the indices inside the set, and since L7c joint shrinking moves two equal indices together, so the `Index<4>` runs reach exactly (0, 0, 1); raw `u8` actors still stop at (1, 1, 1) because equal values are grouped by value and the amount 1 is in the same group.
- Observations about the ERC20 test fixture (not bugs): `transfer`/`transferFrom` return `false` instead of reverting on a shortfall, so "reverts" in the brief is checked as "does not succeed"; `mint` is open to anyone.

### Stateful ERC20 (sonatina only): the ERC20 test fixture from the Fe compiler repo vs a pure reference model

## Panic recovery: properties whose code panics (new APIs; `check` is unchanged)

A panic inside a property used to end the whole test with no report. Expected results were committed before the results commit (docs/EXPECTATIONS.md, section "L7b"). The same seed gives the same input stream on every backend,
so the first failing case, the shrunk input and the number of shrink steps are expected to be identical. Case numbers are 1-based.

- **sonatina**: `check_isolated` runs each evaluation inside a harness contract called through `evm.try_call`; a panic is a failed call, and the reason is read from the revert data (`Panic(0x11)`, `Panic(0x12)`).
- **native**: a panic aborts the process, so `scripts/find-panic.sh` drives the replay executable: it bisects the case limit to the first aborting case, then shrinks by replaying candidates as single-case runs (the reason is the process's stderr text).
- **wasm** (the demo page): the panic is a trap thrown into JavaScript; the page bisects and replays the same way (overflow property only).

#### What the new paths do not cover

- A property that loops forever or runs out of gas: on sonatina the call fails without a panic code and is reported as "failed without data" (a failure of unknown reason); native and wasm would hang until stopped.
- A panic in the generator or the shrinker themselves (they run in the test, not in the harness).
- On sonatina the harness is a user-written contract (Fe contracts cannot be generic): one `recv` arm per property, one line each; inputs must have a `Decode` impl (all built-in generators except `Seq` do).
- Native recovery is a script around a separate executable, not a call inside the test, and reports only the process's stderr text; wasm recovery is shown for one demo property.
